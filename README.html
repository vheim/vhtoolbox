vhtoolbox

R toolbox by Vital Heim for movement ecology and telemetry, statistics, data wrangling and visualisation.

A growing collection of (mostly documented and hopefully) reusable R functions and scripts from my analyses of animal movement data (e.g. satellite and acoustic telemetry of sharks): data cleaning and filtering, spatial calculations, statistics and plotting. Whenever possible, functions are written so they work with any data layout (column names are arguments).

New tools are added as they come up in projects.

Installation

The functions are not a package yet. Just load them all with source():

fun_dir <- "path/to/vhtoolbox"
for (f in list.files(fun_dir, pattern = "^Rfun_.*\\.R$", full.names = TRUE)) source(f)

I do my best to document all functions in roxygen2 style. However, life, time constraints, other projects, fieldwork, etc. may keep me from properly documenting functions, so that fully documented versions of some functions may only be available at a later time.

Why an additional end-location check?

argosfilter::sdafilter() (Freitas et al. 2008) cannot test the first two and last two locations of a track: its speed step needs two neighbours on each side, and it overwrites the angle result for rows 2 and n−1 with "end_location". Implausible end locations, e.g. the first fix after tagging, therefore stay in the track. sdafilter_plus() applies the same two tests to these locations (angle: argosfilter’s own result; speed: root mean square over the neighbours that exist). The first location (tagging location) is never tested.

argosfilter::sdafilter()                  separate step, run first
sdafilter_plus()
 ├─ sdafilter_ends()                      angle test, rows 2 and n−1
 └─ .argos_end_speed_check()  (internal)  speed test, rows 2, n−1, n
         └─ geosphere::distGeo()          (WGS84 distances)
Requirements: location class Z removed; at least 5 locations per individual; POSIXct times; no NA in coordinates or times.

Conventions

  • One function per file, named Rfun_<topic>_<name>.R (e.g. Rfun_sdafilter_plus.R). Internal helpers start with a dot (.prepare_track()) and live in the file of the function that uses them.
  • Documentation in roxygen2 style (#' @param, @return, @examples, @references)
  • Data columns in functions are arguments (lat = "lat", datetime = "date"), not fixed names.
  • No hidden global objects: every parameter is an argument; species-specific values have no default.

If you want to contribute to this repo you are very welcome to do so. Adding a function: write Rfun_<topic>_<name>.R → add an example → add a test to an eval_ script → add a row to the table above. Add your name to the authors list below.
